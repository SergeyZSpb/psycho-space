---

«ВАНЯДУМ» runs a **fixed-step simulation at 20 Hz**, in the server, over a world that lives entirely in memory. This is a new kind of thing in this system, and this record exists because the obvious objection — *"nothing in this project runs on a timer"* — is correct about the rule and wrong about what it forbids.

_What this record used to say, and what was reversed._ It shipped with a second claim beside the tick: **one arena per run, keyed by account**, so that every player had a private заброшка nobody else could walk into. That half was **reversed on the owner's decision of 2026-08-02**. There is now one building for the whole process, joining it is opening a socket, and there are no runs at all — the same shape the sibling office arrived at independently ([ADR-056](./ADR-056-the-office-is-one-process-wide-arena-not-one.md)). What it bought is the reason it was worth reversing: this game's netcode was built multiplayer-complete before there was a second player ([ADR-052](./ADR-052-the-netcode-is-built-multiplayer-complete.md)), and a world per player is exactly the arrangement in which none of it can ever run. The whole argument — the world, the visit that replaced the run, the capacity, the teardown — is [ADR-060](./ADR-060-there-is-one-zabroshka-nothing-ends-and-a-run.md). **What did not move is everything else in this record**: the tick, its rate, its purity, its budget and its distance from the database are what they were.

_Why the yard's mechanism does not transfer._ «Ванягоччи» gets away with no simulation at all, because everything it draws is closed-form: a position is `pattern(params, now − epoch)`, so a tick that is late, early, skipped or duplicated still produces the correct world ([ADR-042](./ADR-042-everything-that-moves-is-a-function-of.md)), and every stat decays from a `(value, as_of)` pair computed on read ([ADR-038](./ADR-038-time-varying-state-is-computed-on-read-never.md)). **Collision destroys closed form.** Where a player is at *t* depends on every wall he slid along on the way there, which is a path integral rather than an expression; there is no `position(t)` to write down. So it has to be integrated, step by step, at a fixed rate — a variable step would make the same input produce different outcomes on a fast phone and a slow one, which is both unfair and untestable.

_Why this does not reopen ADR-038._ That record is about **durable** state: no background job may sweep a table, expire a row, or advance a stored value, because the moment one exists every read has to wonder whether it has run yet. Every clause of it is honoured here.

- The tick touches **memory only** — the same discipline the yard's 5 Hz broadcast already follows in reading from a display cache and never from the pool ([ADR-041](./ADR-041-the-broadcast-tick-renders-from-a-cache-and.md)).
- **Postgres is touched once per visit:** one summary row, written when somebody's last connection has been gone past the grace. Never on a tick, and nothing at all when a player arrives — the building is generated in memory, so walking in writes no row. The one `INSERT` this game makes is queued to a separate writer goroutine, so a slow database delays a row and never a simulation.
- The world is **ephemeral by design and by admission**. A restart loses the building and everybody standing in it, in the same way and for the same reason the hub loses presence — and it loses no *run*, because there are none: nothing was in progress, so nothing is interrupted, and the next hello builds another заброшка. The alternative is persisting a world twenty times a second, which is the thing this whole design exists not to do.
- The ticker is **injected** ([ADR-034](./ADR-034-the-broadcast-tick-is-injected-and-belongs-to.md)): `main` passes a `time.Ticker` and every test passes a channel it fires by hand, so "advance exactly thirty-two steps and then look" is a thing a test can say and there is not one sleep in the suite.

_The level is not state either._ It is a pure function of a seed ([ADR-050](./ADR-050-the-level-is-generated-on-the-server-and-sent.md)), so what survives a visit is eight bytes and a summary, and the geometry is reproducible rather than stored.

_The world is not a room, and the platform never learns what one is._ Everybody is in the same building now, which makes membership of the room and presence in the заброшка the same fact — and the frames are still addressed to a **connection** through `PublishTo` rather than broadcast, because a snapshot names everybody except its own reader, so no two occupants may be sent the same bytes. A room per run was refused for the reason [ADR-045](./ADR-045-a-location-is-not-a-room-the-roster-is.md) refused a room per location: it would push a game's vocabulary into the unprefixed platform file that the naming convention exists to keep clean. There are no runs to make a room of now, and the arrangement that replaced it is the one that was already there: `httpapi` holds a **map of room name to handler**, so the set of valid rooms is exactly what the composition root registered — and each game exports its own room name, so no unprefixed package spells out the name of a game. The realtime layer needed no change whatever to carry a shared world instead of private ones, which is the seam working as intended.

_Authority, and the two things it required._ The client sends **intent and never a fact** — the axes it is pushing and where it is looking, never a position, a health value or a claim to have hit something. Two consequences fall out and both are load-bearing.

**`Step` is pure.** It takes a level, a player and a command, and returns the next player; it reads no clock, holds no state and never queries anything. That is what makes movement table-testable without a socket, and it is what lets the same function run in the browser for client-side prediction, pinned to the Go original by golden vectors ([ADR-052](./ADR-052-the-netcode-is-built-multiplayer-complete.md)). Do not give it a clock, a random source or a map iteration.

**Determinism now has a second requirement, because there is more than one player to order.** The same seed and the same input transcript must still produce the same world, so nothing may let Go's randomised map order decide anything: the wire and the rewind buffer are filled in a **stable** order (occupants sorted by account), and the step loop runs that order **rotated by the tick**. Two orders rather than one, because they answer different questions — an array that reshuffles between frames is a golden test that flaps and a client asked to re-key its bookkeeping for nothing, while a *fixed* simulation order is a standing advantage: collecting mutates world-wide state, so whoever steps first takes a contested bottle, and one sorted order hands that to the lexicographically smaller account for the life of both. Rotating by the tick keeps the replay property exactly — the tick is part of the world's state — while the advantage moves on every 50 ms.

**Simulated time is spent, not claimed.** The socket permits ten frames a second and each may carry four sub-steps of up to 0.2 s, so a client that filled every frame would ask for eight seconds of simulation per real second — running eight times faster than everybody else with **no single field out of range anywhere**. So each **occupant** accrues a time budget at exactly real time and spends it on the commands they send, with a half-second cap so an honest burst from a backgrounded phone can still catch up. This is the guard that a per-field clamp cannot be: every individual value in that attack is legal, and only the total is not. It is per occupant rather than per world for the obvious reason and one less obvious one — a shared budget would make one player's catch-up burst come out of everybody else's simulation.
