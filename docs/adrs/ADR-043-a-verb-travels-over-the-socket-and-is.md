A «Ванягоччи» verb arrives as one `vanyagotchi_do` frame carrying a list of catalogue keys, and `Service.Do` is the only place a verb is ever interpreted — the same function a replay folds over a whole history. **Nothing is sent back in reply.** What the server decided becomes state instead, in two forms: a line over the player's own Ваня, carried to the entire yard in the next 5 Hz roster, and a `vanyagotchi_state` frame unicast to every connection that account has open. There is no HTTP form of a verb; the `POST /api/game-vanyagotchi/actions/{action}` route that was one is deleted, and the route group is two reads and nothing else. The socket's ten-frames-a-second allowance is not a verb's allowance: a batch is capped at one per account per second and at eight verbs per frame.

_Reasoning:_ three separate things, and the third is the one that cost a bug to learn.

**One funnel, because a rule enforced on one path and forgotten on another is not a rule.** [ADR-044](./ADR-044-a-pets-history-is-an-append-only-event-log.md) already made `apply` the only place a single event means anything; `Do` is the only place a *batch* does, and the live path and a replay both go through it. Adding a transport must not add a second interpreter, so the frame handler does exactly what the HTTP handler did — bind the account, check the bound, call `Do` — and nothing else. That is also what made the old route *deletable* rather than merely unused: it had always been a thin adapter onto this function, so moving the last callers off it removed a door and not a room.

**The socket, because a verb owes no reply — and something that owes no reply should not be shaped like a request.** The 5 Hz roster is already the reconciliation channel, and it is full state rather than a delta precisely so that a dropped frame costs nothing ([ADR-034](./ADR-034-the-broadcast-tick-is-injected-and-belongs-to.md)); a tap has always been answered that way and never by an acknowledgement. A verb answered with a body would give one fact two ways of being reported, which is the second path to the same outcome that `CLAUDE.md` forbids — and the two can then disagree. Once nothing is awaited, a whole class of client bug stops being possible: no request in flight for a navigation to cancel, no global error modal thrown over a situation the screen is already explaining, and no retry, because the server stamps the instant and a verb re-delivered a minute later would be integrated at the wrong one.

**A refusal is state in a balloon, never a reply, and that is what makes it survive being dead.** The wire's standing policy is silence — a malformed or unwelcome inbound frame gets no answer and no log line, because a reply per bad frame at the permitted rate is a flood lever — so a refusal expressed as a reply would have had to be an exception to that, and instead it is not a reply at all. Being state buys two further things. It has an expiry rather than a delivery, so a player who arrives late sees whatever is currently true and nothing has to be replayed to them. And the whole yard reads it, which is most of the joke: everybody watches somebody else's Ваня refuse to get up. **The ordering inside that is load-bearing and was learned the expensive way.** The server's line outranks every other thing a Ваня might be saying, *including* being dead: the dead branch used to come first, so a corpse said nothing at all — and the one moment a player most needs to be told «он не встаёт» is exactly the moment his Ваня is dead and a verb has just been refused. He is not speaking; the server is telling his owner something, and being dead does not disqualify him from carrying it.

_Consequence — where a movement gate goes when one arrives._ Standing next to a thing may condition a verb: arriving at the vendor before drinking is a rule the world objects will want. That check belongs in `Do`, against the in-memory placement, evaluated at the instant the batch is folded — not against a stored coordinate. Position is durable only in the weak sense [ADR-041](./ADR-041-the-broadcast-tick-renders-from-a-cache-and.md) gives it: written when an account's last connection goes away, and lost outright in a crash. That is enough for this, because the gate asks a question about *now* and stores no answer, so there is nothing for a lost position to make wrong afterwards — the player simply walks over again. No verb is gated on movement yet; this records where the gate goes, so the first one does not invent a second answer.

_Considered and rejected: keeping the HTTP route beside the frame, "for a client without a socket."_ There is no such client, and there cannot usefully be one: the yard is only drawn from the roster, so a verb pressed without a socket is a verb pressed on a screen that could not show what it did. Keeping the route would have meant maintaining a path whose only caller was its own test — which is precisely the shape `CLAUDE.md` names as legacy, and the reason the deletion is part of this decision rather than a follow-up to it.
